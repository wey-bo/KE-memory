# Git-Backed Memory History Design

**Date:** 2026-07-28

**Status:** Approved architecture, isolated implementation

## Decisions

The user approved these choices:

1. A checkpoint commit contains a short batch of already closed TurnBundle transactions.
2. Each long-lived memory workspace owns a separate local Git repository.
3. Git is the authoritative version history. Databases and indexes are rebuildable projections.
4. Normal forgetting appends a tombstone. Explicit permanent deletion creates a new purged repository epoch.
5. Raw turn text, EvidenceSpan data, L1/L2 records, and provenance are committed to Git. Large media stays in a content-addressed object store and Git commits its hash-bound reference.

## Scope And Isolation

This wave adds a representation-neutral Git history layer. It does not change the locked ontology, L1 extraction, L2 extraction, query compilation, symbolic executor, identity, membership, or embedding fallback modules.

The H100 Codex plugin is currently implementing Typed Extractor v2 L2 dev qualification. This implementation owns only:

- tools/natural_memory_benchmark/git_memory_history.py
- tools/natural_memory_benchmark/git_memory_history_cli.py
- tests/natural_memory_benchmark/test_git_memory_history.py
- this design and its implementation plan

It must not modify typed_extractor_l2 files, the central cli.py, shared status documents, frozen artifacts, or protected hashes while the other task is active.

## Authority Model

Every memory workspace has one local bare Git repository. A bare repository avoids a mutable runtime checkout and lets Git plumbing publish a complete tree through one atomic ref update.

The authoritative ref is refs/heads/authoritative. History is append-only within one repository epoch: no amend, rebase, or force update. Each checkpoint has exactly one first parent and publication uses compare-and-swap update-ref.

Git commit time mirrors checkpoint transaction time for operator convenience, but it is not semantic authority. event_time, valid_time, and explicit transaction_time remain inside canonical records and manifests.

## Canonical Tree

Each commit exposes a complete snapshot:

    repository.json
    epochs/<epoch-id>.json
    state/current.json
    checkpoints/<sequence>-<checkpoint-id>.json
    records/turn_bundle/<logical-id>/<revision-id>.json
    records/l2_bundle/<logical-id>/<revision-id>.json
    records/tombstone/<logical-id>/<revision-id>.json
    records/blob_ref/<logical-id>/<revision-id>.json
    records/purge_manifest/<logical-id>/<revision-id>.json

IDs are path-safe opaque identifiers. Artifact paths are generated by the history layer and cannot be supplied by callers.

Each artifact commits its kind, stable logical ID, immutable revision ID, transaction time, canonical payload, payload SHA-256, and explicit typed references. The Git object ID protects the physical snapshot. Artifact SHA-256 and representation-neutral revision IDs protect semantic payloads independently of Git's object format.

## TurnBundle Adapter

The adapter accepts one TurnBundleRevision, its referenced SourceRecordRevision values, and its referenced L1 MemoryUnitRevision values. It runs validate_turn_bundle_closure before creating a history artifact.

The committed payload contains the complete bundle revision, full raw source revisions including text, and all L1 revisions named by the bundle. raw_only, complete, and failed extraction states may be committed because all three are closed transaction outcomes. A failed bundle still cannot contain partial L1 membership.

This preserves:

    L1 revision -> EvidenceSpan -> SourceRecordRevision -> raw text

L2 writers remain outside this wave. The generic l2_bundle artifact requires explicit references so a future accepted writer can preserve:

    L2 revision -> L1 revisions -> evidence -> raw turn revisions

## Checkpoint Publication

A checkpoint contains workspace and epoch IDs, a contiguous sequence, previous checkpoint ID, transaction time, sorted artifact descriptors, checkpoint ID, and manifest SHA-256.

The repository prepares blobs and a tree through a temporary Git index. It creates a commit with commit-tree and publishes it with compare-and-swap update-ref. Concurrent writers may create unreachable objects, but only one can advance the authoritative ref from the expected parent.

Retry is idempotent by checkpoint ID. Replaying an already published byte-identical checkpoint returns its existing receipt. Reusing an ID with different content fails closed.

The recommended trigger is configurable and outside semantic identity: at most 32 closed TurnBundles, 30 seconds, or explicit session close or flush.

## Projection And Recovery

Online relational, graph, lexical, and vector stores consume authoritative commits in first-parent order. A projection records its last applied Git commit and checkpoint ID.

Projection failure never rewrites Git. It retries idempotently from the last successful checkpoint. If every projection is lost, the materializer can rebuild from the current repository epoch without model calls.

The verifier checks repository metadata, first-parent linearity, contiguous checkpoint sequence, manifest hashes, deterministic IDs and paths, artifact payload hashes, reference closure, and epoch consistency.

Checkpoint verification binds each manifest to its exact generated physical path. At sequence N, the tree must contain exactly the immutable checkpoint manifests for sequences 1 through N; future, missing, renamed, or rewritten checkpoint entries fail closed. The verifier also rejects every path outside the canonical tree.

Logical IDs are globally namespaced across artifact kinds. Multiple revisions of one logical artifact remain valid, but the same logical ID cannot identify both a turn bundle and an L2 bundle, tombstone, blob reference, or purge manifest. This keeps logical-ID hard-purge targets unambiguous without changing the approved request shape.

A repository instance performs a full verification at initialization or whenever the authoritative ref changes outside its verified head. Normal compare-and-swap checkpoint publication then advances the verified head through the incrementally validated construction path. The explicit verify command remains a full offline audit.

## Forgetting And Permanent Deletion

Normal forgetting appends a tombstone. Materializers exclude the target from active views while historical bytes remain auditable.

Permanent deletion is never an automatic extractor action. It requires an explicit HardPurgeRequest bound to the exact source epoch, exact source head, target logical IDs, authorizer, reason, and authorization time.

The implementation creates a new bare repository at a new path. It computes transitive reference closure, excludes targets and dependents, preserves retained artifact bytes, adds a purge manifest containing only fingerprints, and starts a new epoch. It does not delete or swap the source repository.

Activation is external: verify the new epoch, rebuild projections, switch the workspace pointer, explicitly authorize old-repository and blob deletion, then remove stale mirrors and backups. The two-repository preparation prevents a failed purge from destroying the last recoverable history.

## Error Handling

The layer fails closed on invalid hashes, unsafe IDs, incomplete TurnBundle closure, immutable path collision, sequence or head mismatch, dangling references, Git failure, incomplete purge closure, or an existing purge destination. No error path advances the authoritative ref.

## Acceptance Tests

The focused suite proves deterministic initialization, raw and L1 closure recovery, contiguous checkpoints, idempotent retry, stale-writer rejection, tamper detection, tombstone history, safe purge-epoch preparation, unchanged source history, and Git-only verification.

This wave proves a Git-backed authoritative history contract and recovery path. It does not authorize automatic L1/L2/identity/membership writes or select Extended-AMR, KEOL, or another carrier as the final representation.

## Implementation Evidence

The final isolated implementation passed 36 focused Git-history tests, 63 adjacent TurnBundle/authoritative-memory tests, and the current complete natural-memory suite with 364 tests. Compileall, tabnanny, and the 100-character line scan were clean. The migrated workspace `.git` directory remained empty; the implementation creates only separate bare memory repositories.
