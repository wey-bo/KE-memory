# AMR 单句表示小实验设计

状态：设计已由用户确认，尚未实施。AMR 仍是候选表示，不是当前记忆架构事实；只有本实验通过并再次得到用户与 Agent 共同确认后，才能进入跨句节点实验。

## 1. 目标与阶段边界

本实验只验证两个问题：

1. 标准 AMR 能否在单个英文句子上比当前原子知识表示更完整、准确地保全语义；
2. 先抽取原子知识再转写为 AMR，是否能以可接受的额外成本提高 AMR 质量。

本实验不验证长期记忆效果，也不设计摘要、跨句或跨 session 表示、问题解析、查询、检索、embedding 或 benchmark 适配。单句实验通过只表示 AMR 可以进入下一阶段，不表示 AMR 已成为存储模型、KE 替代品或正式节点接口。

原文始终是恢复底座。AMR、原子知识、后续摘要和高层表示都必须能够回指原始文本及来源坐标。

## 2. 输入与抽样

首批固定为 12 个独立英文句子，从现有 `KE-test` 候选的公开原始英文来源按来源坐标重新读取，不使用当前中文展示译文。每个样本只包含一个完整句子，不加入前后轮上下文，不混入跨轮指代或工具调用/工具结果组合。

样本按四类语义现象分层，每类 3 条：

- 事件与参与者角色；
- 时间、数量和条件；
- 否定、模态和意图；
- 因果、比较和多分句关系。

样本选择必须保留原始顺序、数字、日期、地点和产品名，不得修正源数据中的事实、逻辑或表达。12 条只用于方向性阶段门，不用于宣称统计显著性。

## 3. 独立语义检查表

正式运行前，为每个句子建立独立的语义检查表。检查表直接从原始英文句子生成，不读取三条待测链路的结果，也不把现有知识抽取或 KEOL baseline 当作 gold。

每个检查项至少记录：

- 原句和来源坐标；
- 核心事件或状态；
- 参与者及角色方向；
- 时间、数量、条件、否定、模态和因果；
- 明确不应出现的推断；
- `critical` 或 `ordinary` 重要性；
- 人工确认状态和裁决说明。

Agent 可以生成候选检查表，但必须由用户确认后才进入 `gold_approved` 状态。权重随 gold 显式保存并接受人工确认，不能作为评分代码中的隐藏默认值。

## 4. 三路消融

每个句子进入以下三条逻辑链路：

```text
A. 原始英文 -> 标准 AMR
B. 原始英文 -> 原子知识 -> 标准 AMR
C. 原始英文 -> 原子知识基线
```

C 与 B 的第一阶段使用同一份原子知识结果，不重复调用模型。这样可以保证 B 与 C 的知识输入完全一致，并避免把重复采样差异误认为 AMR 转写收益。B 的端到端成本包含知识抽取和 AMR 转写两次调用。

当前原子知识记录承担 C 的语义基线；本实验不强制把它投影为 KEOL Assertion，因为额外的本体归一和 builder 行为会混入新的实验变量。KEOL baseline 和此前结果只作工作区历史比较项，不作为提示输入或语义来源。

## 5. 模型与运行协议

用户已取消 `subagent 5.4` 限制。所有待测语义生成步骤固定使用当前可用的平衡型 `gpt-5.6-terra`，并把该精确模型标识写入 payload 和 sidecar：

- 原始英文生成 AMR；
- 原始英文抽取原子知识；
- 原子知识转写 AMR。

三路固定提示词版本、上下文范围、温度和输出预算。每项默认只运行一次，不进行多次采样后择优。正式实施前必须验证当前运行环境能够明确指定 `gpt-5.6-terra`；如果模型选择再次变化，必须先记录新的用户授权并更新 payload、sidecar 和报告中的模型标识。

只有 PENMAN 无法解析时允许一次格式修复重试。首次失败必须保留并计入首次成功率；修复结果保存为新的 attempt，不能覆盖原始输出。格式修复提示只能指出解析错误，不能要求模型重新解释或补充句子语义。

效率按端到端口径记录：墙钟耗时、输入 token、输出 token、总 token 和可核对的成本。若 subagent 接口不能提供可靠 usage 或价格依据，成本指标标为不可用，并在阶段裁决前显式处理，不能用估算值冒充实测值。

## 6. AMR 输出契约

AMR 本体使用标准 PENMAN 图表示、PropBank frame 和标准角色。项目元数据不得写入 AMR 图，而是保存在 sidecar JSON 中。sidecar 至少记录：

- sample、route、run 和 attempt ID；
- 原文、来源坐标和文本哈希；
- 模型标识、提示词版本及哈希；
- 开始/结束时间、耗时和 usage；
- 首次解析结果、修复记录和错误；
- `representation_gap`；
- 原始输出文件和解析产物引用。

无法用标准 AMR 表达的来源状态、证据、生命周期或项目字段必须写入 `representation_gap` 或外部元数据，不能静默扩展图语法。PropBank 与 PENMAN 解析器的版本必须在实施计划中固定。

## 7. 评分与错误分类

评分分为两层：

1. 程序检查 PENMAN 可解析性、引用闭合、frame/role 合法性、文件完整性和运行元数据；
2. 独立语义评审把匿名化输出映射到已批准的语义检查表，判断支持、遗漏、错误和无依据新增。

独立评审不能把生成模型的自评作为唯一依据，也不能看到 A/B/C 路由名称。争议项由用户最终裁决。

关键错误包括：参与者或关系方向反转、否定反转、模态改变、错误时间或数量、条件关系改变、因果反转以及无依据新增核心事件。普通词义粒度或不影响原意的标签差异不自动算关键错误。

三种表示统一按语义检查项计算加权 precision、recall 和错误数，不直接比较 AMR 节点数与知识条目数。报告同时按四类语义现象列出逐句结果和失败案例。

## 8. 平衡型阶段门

候选路径必须同时满足以下条件：

- 12 条最终输出均可解析，至少 11 条首次生成即可解析；
- 加权语义 recall 不低于 90%，precision 不低于 95%；
- 不存在未解决的角色反转、否定反转、错误数字等关键错误；
- 与原子知识基线相比，AMR 至少在一个预定义难点类别中净修复 2 个错误；只改变格式或增加节点不算收益；
- 知识前置 AMR 只有在比直接 AMR 提高至少 5 个百分点，或额外修复至少 2 个关键错误且不引入新关键错误时，才保留为候选；
- 直接 AMR 的端到端 token 和耗时不超过原子知识基线的 1.5 倍；知识前置 AMR 不超过 2.5 倍；
- 质量差异不足 5 个百分点时选择更便宜的路径。

任一硬门失败时，结论只能是停止或继续有针对性的小实验，不能进入跨句节点层。报告使用错误数量、逐例证据和效率数据解释结论，不把 12 条结果包装成统计显著结论。

## 9. 工具与产物布局

实施时沿用工具和产物分离的工作区约定：

```text
tools/amr_pilot/
  输入准备、PENMAN 校验、指标计算和报告生成

artifacts/amr-pilot/
  inputs/
  gold/
  prompts/
  runs/<run_id>/raw/
  runs/<run_id>/sidecar/
  reports/
```

输入、gold、提示词和模型原始输出均按稳定 ID 和哈希追踪。原始输出不可覆盖；重试、人工裁决和派生评分使用新文件或追加式记录。实验状态依次为：

```text
draft -> gold_approved -> executed -> scored -> adjudicated
```

只有 `adjudicated` 报告可以用于节点决策。设计确认本身不创建 `tools/amr_pilot/` 或 `artifacts/amr-pilot/`，这些目录由后续实施计划创建。

## 10. 节点通过后的候选路径

只有单句阶段通过并再次得到用户与 Agent 共同确认后，选中的 AMR 路径才成为候选节点生成器。跨句阶段暂时只保留三条候选路径，不提前选择：

```text
1. 节点集合 -> 模型摘要 -> 高层 AMR
2. 节点集合 -> 模型摘要 -> 高层 KE
3. 节点集合 -> 直接高层知识/KE
```

第 3 条是无摘要对照，用于识别摘要造成的信息损失。高层结果必须回指底层节点和原文，不能只绑定摘要文本。问题解析、查询表示、召回和融合规则在该节点通过后另行设计。

## 11. 最终 benchmark 与外部基线

LoCoMo、BEAM 和 LongMemEval 不进入单句 Prompt 调整。只有节点、高层抽象、问题处理和检索方案分别通过后，才按开发切片、针对性 probe、正式评测的顺序测试本项目方法，并分别使用各 benchmark 的原生数据划分和指标。

其他 memory 系统一律不在本项目中安装或复跑。mem0、MemPalace 和 Hindsight 是优先收集项，但外部系统列表保持开放：只要存在目标 benchmark 上可追溯的作者结果，就可以纳入。来源优先级为官方仓库评测记录、作者论文及补充材料、作者维护的项目页面。

每条外部结果必须记录系统版本或日期、benchmark 版本、数据切片、基础模型、上下文设置、指标定义和原始链接。只有数据、切片和指标兼容的结果才能直接并排；协议或模型不同的结果单列为“作者报告参考”。最终报告严格区分“本项目实测”“其他系统作者报告”和“不可比较”，不使用第三方博客补数，也不把 benchmark qid、gold answer 或自然语言模板写成产品语义。

## 12. 实施前仍需确定

- 12 条英文句子的具体来源坐标和分层归属；
- 经用户确认的语义检查表、重要性和权重；
- 独立匿名评审的执行方式；
- 已授权的 `gpt-5.6-terra` 的可指定性以及 usage/成本数据可得性；
- PENMAN 解析器和 PropBank 版本；
- 运行 ID、sidecar 和评分文件的精确 JSON schema。

这些事项进入后续实施计划，不得在代码中用未经确认的隐含默认值代替。
